title: "ADR-0010 amendment of 2026-09-24: a loading Splash is Starting while its process is up and its address unbound, found in the process table"
---

> **Amended 2026-09-24** by ADR-0015. The definition above ("process up, address bound") holds for llamacpp. Splash binds its address only once its Model has loaded, so a loading Splash is Starting while its process is up and the address is still unbound. The launcher finds it in the process table: a process-group leader running a Splash server launch with the address's host and port, counted only while nothing listens there. Discovery, the start refusal, identification and stop verification apply to it unchanged. The Consequences bullet saying only `llamacpp` implements `StartupProber` is also out of date: Splash implements it too, and adds `LoadingProcessFinder`.
